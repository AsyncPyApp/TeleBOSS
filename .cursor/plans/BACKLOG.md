# Backlog / Future

Очередь идей и работ, которые **не делаем прямо сейчас**. Активные планы и задачи живут в `*-plan.md` + `{{PLAN_ID}}/BOARD.md`; сюда попадает всё отложенное.

Связь с оркестрацией: [README.md](README.md) · skills `idea-to-plan` / `plan-to-tasks` / `task-executor` · правило `.cursor/rules/backlog.mdc`.

---

## Правила добавления

Добавляй сюда пункт, если выполняется **хотя бы одно**:

1. **Не сейчас** — оператор или план явно откладывают работу («потом», «не в этом PR», «после релиза»).
2. **Вне текущего плана/задачи** — идея всплыла mid-flight, но не входит в goal / out of scope активной задачи.
3. **Ломает совместимость или объём** — нужен отдельный осознанный релиз, `MIN_VERSION`, миграция или долгий эпик (не «заодно» с текущим фиксом).
4. **Архитектурный долг** — дедуп, перенос файлов, снятие шимов, DDD и т.п., пока strangler/shim-контракт ещё держим.
5. **Нет ясности** — идея ценная, но нет решения оператора; фиксируем черновиком, не начинаем код.

**Не** клади в backlog:

- то, что уже есть как `ready` / `in_progress` / `blocked` на BOARD;
- однострочные баги текущего спринта (сразу `idea-to-plan` или задача);
- секретные/локальные заметки без продукта.

### Формат пункта

| Поле | Содержание |
|------|------------|
| **ID** | `Bnn` (монотонно) |
| **Title** | Краткая суть |
| **Why later** | Почему не сейчас |
| **Notes** | Контекст, риски, ссылки на планы/код |
| **Status** | `idea` → `ready_for_plan` → `planned` → `done` / `dropped` |
| **Promoted** | Когда ушло в `idea-to-plan`: путь к `*-plan.md` или `—` |

Статус `ready_for_plan` — можно звать `idea-to-plan`. `planned` — уже есть PLAN/BOARD; пункт не удаляем, пока эпик не `done`.

### Дисциплина агентов

- Всплыло «хотелось бы ещё…» вне scope → **добавить/обновить backlog**, не расширять текущую задачу без оператора.
- Перед новым большим рефакторингом — **сначала проверить**, нет ли уже пункта здесь.
- Снятие шимов / breaking API → только через backlog → plan → осознанный релиз (см. versioning).
